# [코멘트 초안] #781 — 고객 편집형 도메인 예외 사전을 이 트리로 흡수

> 대상: #781 코멘트 (신규 이슈 아님)
> 기획 사이클: 2026-08-pilot · 2-plan.md 후보 #1 [M] · 승인: 4-decision.md (2026-08-13)

## 결정

2026-08-pilot 기획 사이클의 후보 1 "고객 편집형 도메인 예외 사전(PII/독성 allowlist)"이 승인됐고, **신규 이슈를 만들지 않고 #781 트리의 하위 티켓으로 접는다.**

흡수 근거는 이 티켓 본문의 "개선 방향 제안 §2 도메인 프로파일 개념 도입"이다. 거기서 이미 PII 엔티티 on/off(#464)·값 예외(#734)·게이트 예외(#719)·JB threshold(#767)를 고객사/도메인 단위 프로파일로 묶자고 제안하고 있으니 같은 축이고, In progress에 코멘트 32건이 쌓인 우산 티켓에 별도 신규 발주를 얹으면 중복이다.

## 이 사이클이 더하는 것

### 시장·경쟁 근거

- 오탐 억제 **전용** 메커니즘은 확인된 6개 벤더 어디에도 문서가 없다. Lakera의 커스텀 정규식은 "탐지를 추가"하는 방향이고 allowlist·예외 사전은 미확인이다. [공식] https://docs.lakera.ai/docs/content-moderation · 확인일 2026-08-12 (G§Q5-a)
- Bedrock은 엔티티 개별 on/off와 NONE 액션(탐지만 하고 조치 없음)까지가 전부다. [공식] https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-sensitive-filters.html · 확인일 2026-08-12 (G§Q5-a)
- 국내에서는 이로운앤컴퍼니가 LUBS(과잉 차단 완화)로 같은 문제를 겨냥하고 있다. [보도] https://www.datanet.co.kr/news/articleView.html?idxno=201426 · 확인일 2026-08-12 (D§Q5)
- 정리하면 **비어 있지만 경쟁자가 이미 조준 중인 칸**이다. 경쟁사 매트릭스 기준으로 "오탐 억제 전용 기능"을 가진 행은 없고, 최근접이 Lakera의 L1~L4 민감도와 Bedrock의 엔티티 on/off다 (`competitor-matrix.md`)

### 저장소 실측 (확인일 2026-08-12, 기준 커밋 `68338338`)

- **이미 있다**: 값 예외 목록 #734(CLOSED) — `sgt-owasp/src/app/config/json/pii_value_exceptions.json`. match 4종(`exact`/`digits`/`prefix`/`email_domain`), `entityTypes` 필수·`*` 금지, 인명 규칙은 `requireAny` 또는 `acknowledgeNameRisk` 없으면 거부, 적용 지점은 마스킹 직전 span 필터(`pii_anonymizer._filter_entities_by_value_exceptions`), 로드 실패 시 예외 미적용(=그대로 마스킹) fail-safe. 임직원 명부 변환 스크립트와 적용 전 lint/preview 스크립트도 있다
- **이미 있다**: 전파 경로 2종 — Cloud Config 키(무중단), helm `detectionConfig` subPath(롤링 재기동). owasp 쪽 수신 핸들러도 있다(`main.py:739`)
- **없다**: 편집 UI·CLI. 문자열 `pii_value_exceptions`가 `sgt-admin/src`·`sgt-ctl/internal`·`helm/` 어디에도 **0건**이다. 풀구성은 서버 설정 화면(`server/config/*.html`, `sgt_app_config` 일반 CRUD)에 JSON 문자열을 손으로 넣는 경로만 있고 그 절차의 문서화는 `미확인`, 최소구성은 values 손편집이다. 즉 #734는 닫혔지만 **운영자 손이 닿는 경로가 0**이라 현장에서 쓰이지 않았다 — 현대차증권 A/B 문서에서도 "규칙 0개 — A/B 동일"로 실측됐다
- **없다**: 정규식·엔티티 유형 한정 예외(현재 값 단위 4종뿐), 독성·금칙어 축의 예외(값 예외는 PII 전용)
- **감사**: 적중은 owasp 애플리케이션 로그 INFO 한 줄(규칙 id만, 값은 어떤 로그 레벨에도 남기지 않음). admin 탐지 감사 DB `sgt_owasp_api_event` 컬럼에 예외 적중 필드는 없다

### 하위 티켓을 열 때 쓸 완료 판정

1. 같은 규칙을 풀구성 admin 화면과 최소구성 sgtctl 양쪽에서 등록했을 때 **같은 탐지 결과**가 나온다
2. 규칙 등록/수정/삭제가 감사에 남고, 적중 건이 **관리 화면에서 조회 가능**하다 (현재는 애플리케이션 로그에만 남는다)
3. 인명 예외는 보호장치(`requireAny`/`acknowledgeNameRisk`) 없이 저장되지 않는다 — 화면·CLI 양쪽에서 거부된다
4. 예외 규칙 N개를 얹은 상태로 법령 clean 코퍼스(#729 112종) FPR과 평가셋 recall을 재측정해 **미탐 증가분이 합의된 상한 이내**임을 보인다

### 인접 티켓 판정

- **#875 → 분리**. #875는 미탐을 줄이는 소스 레벨 개선(주소 gazetteer 행정동 편입, 금융/카드 브랜드 유한목록)이고 이 후보는 오탐을 줄이는 예외 등록이라 방향이 반대다. 다만 둘 다 `ORGANIZATION`·`LOCATION` 라벨을 건드리므로 **재측정 게이트를 공유**해야 한다
- **#734 → 이미 닫힘**. 이 후보는 #734의 대체가 아니라 운영자 손이 닿는 경로의 확장이다. **재구현하지 말 것**
